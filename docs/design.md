# celldiff 設計

## 目的

2つのCSVファイルをセル単位で比較し、差分をExcel（.xlsx）に出力するCLIツール。
異なるセルについては文字単位の差分も検出し、Excel上で変更部分を強調する。

大きなCSVを扱い、利用者が言語ランタイムを別途導入せずに実行できる配布形態を目指す。
実行ファイルのサイズにも配慮する。具体的なサイズは依存関係を含めてビルドして確認する。

## 決定済みの方針

- プロジェクト名・リポジトリ名・コマンド名は `celldiff`。
- Rustで実装する。
- 入力は2つのCSV、出力はExcel（.xlsx）。
- GUIは作らない。
- まずは差分検出に限定し、マージは実装しない。
- 2つのCSVからレコードを順次読み込み、対応するフィールドを比較する。
- セル単位の一致判定を行い、異なるセルに対して文字差分を計算する。
- Windows・Linux・macOSでビルドとテストを確認する。

CSVの用語では「レコード」「フィールド」を使う。
表としての位置やExcelへの出力について説明する場合は「行」「列」「セル」を使う。
引用符内の改行があるため、CSVのレコード番号とファイルの物理的な行番号は一致しない。

## 比較モデル

### レコードとフィールドの対応

初期実装は、同じレコード番号・同じフィールド位置を対応させる方針とする。
キーによる照合や、挿入・削除されたレコードを検出して後続を再対応させる処理は初期実装に含めない。

この方式では、途中へのレコード挿入や並べ替えによって、その後の比較結果も変わる。
これは文字差分とは別の、レコード対応の問題である。

ヘッダーの扱い、レコード数・フィールド数が異なる場合の扱いは未決定。

### セルの比較

CSVを解析して得られたフィールドの値を、文字列として比較する方針とする。
CSVの引用符などの記法の違いではなく、解析後の値の違いを検出する。

- 数値・日付などへの自動変換は行わない。
- `001` と `1` は異なる値として扱う。
- 空白の除去、大文字・小文字の統一、Unicode正規化は自動で行わない。
- 空フィールドと、存在しないフィールド・レコードの扱いは別途決める。

### 文字差分

異なるセルの旧値と新値を比較し、共通部分・削除部分・追加部分を得る。
途中への文字の挿入・削除を考慮し、同じ文字位置同士を比較するだけの方式にはしない。

「文字」の単位は未決定。
Unicodeスカラー値単位と、結合文字や絵文字をまとめる書記素クラスタ単位の違いを確認して決める。
長いセルの処理時間や、一意に対応が決まらない繰り返し文字列の表示も検証する。

## 処理の流れ

1. CLI引数を検証し、比較元・比較先を開く。
2. CSVライブラリを通して、それぞれから1レコード読み込む。
3. 対応するフィールドについて一致判定を行う。
4. 異なるセルの文字差分を計算する。
5. 出力仕様に従って結果をExcel出力処理へ渡す。
6. 両方の入力が終わるまで繰り返す。
7. Excelファイルを保存し、処理結果を報告する。

片方だけ先に終了した場合の処理は、レコード数の違いをどう表現するかに合わせて決める。

CSVの解析を、物理的な行の読み込みとカンマでの単純な分割で実装しない。
引用符、引用符内の区切り文字・改行、エスケープされた引用符はCSVライブラリに任せる。

## メモリと所有権

入力の全レコードをメモリに保持せず、現在の比較に必要なレコードを保持する。
行バッファを再利用し、セル比較では文字列を借用する。

差分を後でまとめて使う場合、次の読み込み後も必要な値は所有する文字列として保持する。
可能であれば差分を順次出力し、全差分の蓄積を避ける。

CSVを順次読み込んでも、Excelライブラリが出力データを保持する場合はメモリ使用量が増える。
省メモリモードとリッチテキスト出力の併用を検証してから、出力方式を確定する。
一時ファイルの使用量や最大レコード・セルの大きさも考慮する。

## Excel出力

### 求める動作

- 変更があったセルと、その旧値・新値を確認できる。
- セル内の変更部分を文字単位で強調できる。
- 元の文字列を保持し、先頭ゼロなどを失わない。
- 文字列を数式として解釈させず、文字列として書き込む。

文字単位の強調にはリッチテキストの文字色・太字・取り消し線などを使う。
背景色はセル全体の書式であり、文字列の一部分だけに背景色を付ける方式にはしない。

### 未決定のレイアウト

候補は次の2つ。現時点ではどちらも確定していない。

| 方式 | 内容 |
| --- | --- |
| 左右比較 | 比較元と比較先を並べ、対応する変更セルの文字を強調する |
| 差分一覧 | 差分セルごとにレコード番号・列位置・旧値・新値を出力する |

全レコードを出すか、差分のあるレコードまたはセルだけを出すかも決める。
文字色、凡例、ヘッダー表示、番号の起点、差分なしの場合の出力は未決定。

Excelの行数・列数・セル文字数の上限を超えた場合の動作を決める。
分割、エラー、別形式への退避などを無断で選ばず、切り捨てによる情報損失を避ける。

## 採用予定のライブラリ

まだ `Cargo.toml` には追加していない。実装時に必要な機能と互換性を確認して追加する。

| crate | 用途 | 選定理由 |
| --- | --- | --- |
| [csv](https://docs.rs/csv/) | CSVの読み込み | CSVの構文を扱い、レコード単位の読み込みとバッファ再利用ができる |
| [similar](https://docs.rs/similar/) | セル内の文字差分 | 共通・追加・削除を取得でき、文字や書記素クラスタ単位の比較を選べる |
| [rust_xlsxwriter](https://docs.rs/rust_xlsxwriter/) | .xlsx出力 | RustでExcelファイルを生成でき、セル内の部分書式と省メモリ出力機能がある |

文字コード変換・CLI引数解析・エラー処理に使う追加crateは未選定。
GitコマンドやExcelアプリケーションのインストールを実行要件にしない。

依存の指定とビルド設定は `Cargo.toml`、解決された正確なバージョンは `Cargo.lock` で管理する。
CLIアプリケーションなので、Cargoで生成した `Cargo.lock` はGitに含める。
設計書に特定の最新版番号を重複して管理しない。

## 構成方針

責務をCSV入力、セル・文字比較、Excel出力、CLIに分ける。
最初から複数のCargoパッケージに分割せず、単一パッケージ内のモジュールで構成する。

比較ロジックをCLIやExcel書式から独立させ、単体テストで検証できるようにする。
具体的なモジュール名・公開APIは実装時に決める。

## テストとCI

単体テストは実装モジュールのテスト用モジュールに置く。
CSV入力からExcel出力までの確認は結合テストで行う。

検証対象:

- 同一セル、置換、文字の挿入・削除、空文字列、日本語、結合文字・絵文字。
- 引用符内のカンマ・改行、引用符のエスケープ。
- 先頭ゼロ、空白、数式に見える文字列の保持。
- レコード数・フィールド数の違いと、空フィールドの区別。
- 入出力エラーと、出力ファイルが不完全な場合の扱い。
- xlsx内の値と部分書式、Excel上での見え方。
- 大きな入力に対するメモリ使用量、処理時間、出力サイズ。

現在のGitHub Actionsは、push・pull request・手動実行に対して、
Windows・Linux・macOSで `cargo build --release` と `cargo test` を実行する。
現時点ではプロジェクトの骨格のみであり、機能のテストケースは未実装。

## 実装前に決めること

- ヘッダーの有無・比較への含め方。
- 入力文字コード、BOM、変換失敗時の扱い。
- レコード数・フィールド数が違う場合の差分表現。
- 文字差分の文字単位。
- Excel出力のレイアウトと強調書式。
- Excelの上限を超える場合の扱い。
- CLI引数、上書き方針、終了コード、差分件数の表示。

将来のTSV・Excel入力やマージは、初期実装の範囲に含めない。
