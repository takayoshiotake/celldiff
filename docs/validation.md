# 検証記録

## 現在の出力形式（2026-10-15変更）

元のCSVの論理レコード・列位置をExcel座標に対応させる。
差分一覧は廃止し、変更のないセルも元の位置に出力する。
同じセル内で削除・追加を強調し、空セルの追加・削除は背景色で区別する。

## 検証項目

- 入力のA1、B2、C3などが同じExcel座標に残る。
- 変更のない行・セルを詰めず、先頭へメタデータ行・列を挿入しない。
- constant-memoryで複数行にまたがる値・部分書式を保持する。
- 共通部分は1回だけ表示し、削除と追加を同じセルに含める。
- 空値の追加／削除が別の背景色になる。
- 先頭ゼロ、日本語、改行、絵文字、数式に見える文字列を保持する。
- xlsx内に数式を作らない。
- 元の値と差分をまとめた表示の両方に文字数上限を適用する。
- Excel座標上限を超える行・列は、変更なしでもエラーにする。
- 失敗時に出力を公開せず、既存ファイルを保持する。
- 3OSで単体・CLI結合テスト、Clippy、配布実行ファイルのスモークテストを行う。

## 性能測定

scripts/benchmark.pyで一致・疎な差分・全件差分・長いセルを再現する。
変更のないセルも出す方式に変わったため、従来の差分一覧方式の数値と区別する。
[2026-10-14の結果](benchmarks/2026-10-14.json)は旧形式の記録であり、
現在の出力サイズ・時間・一時ディスクを表すものではない。
新形式の測定はCIで確認後に記録する。

測定は/usr/bin/timeのピークRSSとプロセスの経過時間を使う。
20ms間隔で一時ファイルと出力をサンプリングし、削除済みの開いた一時ファイルも/procから数える。
測定値を瞬間ピークの厳密な上限や、異なる実行環境での性能保証とは扱わない。
通常のCIで大きな入力を毎回処理せず、手動CIで再測定できる。

## 配布物

Windows x86_64（静的CRT）、Linux x86_64-musl、macOS ARM64向け。
build-info.jsonにバイト数、SHA-256、ホスト、ターゲット、動的依存を記録する。
配布実行ファイルでもサンプルCSVを比較して座標と文字列を検証する。

## 目視確認

元のxlsxをLibreOfficeでレンダリングしてレイアウトを確認する。
Microsoft Excel本体での表示確認とは区別する。

確認項目:
- 入力と同じ行・列位置で見られる。
- メタデータによる行・列の増加がない。
- 削除部分の赤字・取り消し線、追加部分の青字・太字が見える。
- 元のヘッダー、先頭ゼロ、日本語、改行、絵文字が見える。
- 空値と欠落が背景色で区別できる。
- 修復ダイアログが出ずに開ける。
