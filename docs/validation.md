# 検証記録

## 検証方法

- csv入力の単体テスト、位置対応比較、文字差分の旧値・新値復元を確認する。
- CLI結合テストで実行ファイルを起動し、終了コードと生成xlsxの値・書式を検証する。
- constant-memoryモードの複数行で、前の行の部分文字書式が消えないことを確認する。
- 空値と欠落、引用符内改行、先頭ゼロ、数式に見える値を含める。
- 保存失敗・不正UTF-8・上限超過で完成ファイルが公開されず、既存出力が保持されることを確認する。
- Excel行上限は境界値テストで確認する。100万行のファイルを通常CIで毎回生成しない。

## 出力方式の検証

差分一覧を採用。全入力の左右複製は初期版では行わない。
部分書式とconstant-memoryの併用はtests/cli.rsで実際に保存したxlsxを開き、
inlineStrの元値、色、取り消し線、数式がないこと、複数行の保持で判定する。
実際のExcelアプリケーションによる表示確認とは区別する。

## 性能測定

`scripts/benchmark.py`で10,000／100,000レコードの一致・疎な差分・全件差分を生成する。
長いセルは10,000レコード、100レコードごとの変更として検証する。
入力2件、4列。疎な差分は100レコードごとに1セル、全件差分は各レコード1セル。

Linuxの/usr/bin/timeでelapsedとpeak RSSを取得する。
一時ファイルと出力は20ms間隔でサイズをサンプリングする。
ディスクの瞬間ピークを完全には捉えないため、測定値を厳密な上限とは扱わない。
CPU、OS、Rust、依存のバージョン、入力内容が異なる結果とは単純比較しない。

測定結果はCIで確認後、この文書へ追記する。
手動CIはbenchmark-results.jsonを成果物として保存する。

## 配布物

OS別の成果物にbuild-info.jsonを含める。
バイト数、SHA-256、ホストとターゲット、動的依存の検査結果を記録する。
Linuxはmusl向け、Windowsは静的CRTを使用する。
macOSはOS標準ライブラリを使用し、署名・公証はしない。
配布バイナリを用いた比較・上書き保護・差分なしの検証をscripts/smoke.pyで行う。
